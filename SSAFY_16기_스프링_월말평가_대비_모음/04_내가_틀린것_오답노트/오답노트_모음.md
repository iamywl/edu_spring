## 오답 02. `Notice.java` (DTO) — `public static` 사용 + `catId` 누락 + Lombok 누락
- **스크린샷**: `오답02_Notice_DTO_static사용_필드누락_롬복누락.jpg`
- **틀린 이유**:
  1. `public static`을 붙여서 모든 공지사항이 같은 값을 공유하게 되고 Lombok이 동작하지 않음 → **`private`** 사용!
  2. `catId` 필드 1개 빠짐 (`8개` → **`9개`** 필요).
  3. 클래스 위에 `@Data`, `@NoArgsConstructor`, `@AllArgsConstructor`, `@Builder` 어노테이션 4개 누락.
- **고치는 법**:
  - 클래스 위에 Lombok 4종 세트 붙이고, `private int catId;` 포함 9개 필드를 `private`로 선언!
- **해설 (시험장에서 이걸 어떻게 아나요?)**:
  1. **Lombok 4종 세트**: 명세서에 적힌 한국어를 그대로 영어로 옮기면 됩니다!
     - `기본 생성자` ➔ `@NoArgsConstructor`
     - `전체 인자 생성자` ➔ `@AllArgsConstructor`
     - `빌더 패턴` ➔ `@Builder`
     - `Getter/Setter` ➔ `@Data`
  2. **왜 `private`인가요? (`public static` ❌)**:
     - 명세서에 **"Getter/Setter 접근"**이라고 적혀 있으므로 변수를 `private`로 잠가두고 `getXxx()`, `setXxx()`로만 꺼내 쓰는 게 DTO의 고정 규칙입니다.
     - `static`을 붙이면 공지사항 여러 개가 전부 같은 제목/번호 1개를 덮어써서 공유하게 되고, Lombok(`@Data`, `@Builder`)도 작동하지 않습니다. → **DTO 변수는 고민 없이 무조건 `private`!**
